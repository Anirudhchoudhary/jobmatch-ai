# Phase 1 — Project Skeleton Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A runnable repo skeleton: Python 3.12 backend with lint/type/test tooling, settings loaded from AWS Secrets Manager or a generated `.env`, PII-redacting logging, Postgres+pgvector in Docker Compose with an Alembic migration, a FastAPI `/health` endpoint that checks the DB and pgvector, and a GitHub Actions CI that needs no secrets.

**Architecture:** `backend/` is a uv-managed Python package `app` (FastAPI factory `create_app()`), async SQLAlchemy 2 over psycopg 3, Alembic migrations. Settings via pydantic-settings; secrets come only from Secrets Manager (directly, or via a generated git-ignored `.env`). Root `Makefile` is the single entry point for humans and CI.

**Tech Stack:** Python 3.12, uv, FastAPI, uvicorn, pydantic-settings, SQLAlchemy 2 (asyncio) + psycopg 3, pgvector (Python pkg), Alembic, boto3, structlog, pytest + pytest-asyncio + httpx, ruff, mypy (strict), pre-commit, gitleaks, Docker Compose, `pgvector/pgvector:pg17` image, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-26-jobmatch-ai-design.md` (§4 Constraints, §7.7–7.8 Observability/Security, §11 Repository layout, §12 Phase 1)

## Global Constraints

- Python `>=3.12,<3.13`; type hints everywhere; `mypy --strict` passes on `app/`.
- ruff is the only linter/formatter (`ruff check` + `ruff format`), line length 100.
- **Every secret lives in AWS Secrets Manager.** Nothing secret is committed, hand-written into `.env`, or stored in GitHub. `.env` exists only as a file generated by `make env` (mode `0600`, git-ignored).
- Secret ids: `jobmatch/dev`, `jobmatch/prod`, `jobmatch/ci`. Secret value is one JSON object with keys `ANTHROPIC_API_KEY`, `DATABASE_URL`, `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`, `SESSION_SIGNING_KEY`, `OTP_HMAC_KEY`, `RESEND_API_KEY` (Phase 1 only *requires* `DATABASE_URL`).
- AWS region default `us-west-2`.
- No PII (email, phone) in logs: all log output passes through the redaction processor.
- Unit tests run fully offline (no AWS, no Docker). Integration tests are marked `@pytest.mark.integration` and need the Compose Postgres.
- CI uses no secrets and no AWS access in Phase 1; workflows use `pull_request` (never `pull_request_target`) with `permissions: contents: read`.
- Local DB URL (non-secret, dev-only, used in Compose and CI): `postgresql+psycopg://jobmatch:jobmatch@localhost:5432/jobmatch`.

## Review Focus

1. **DB unreachable or wrong URL at startup** → the app still starts; `GET /health` returns **503** within ~3 s with `{"status":"degraded","db":"error"}` — never hangs, never 500s, never leaks the URL/password. (Task 5 test `test_health_db_down_returns_503_fast`.)
2. **pgvector extension not installed** → `/health` returns 503 with `"pgvector":"missing"`. (Task 5 test `test_health_pgvector_missing`.)
3. **Secrets Manager failure** (secret not found, access denied, invalid JSON) → a `SecretsError` whose message names the secret id and the AWS error code but contains **no secret values**. (Task 2 tests.)
4. **`make env` with awkward values** (quotes, `#`, `=`, spaces, newlines) and an existing `.env` → file is rewritten atomically, mode `0600`, and values round-trip exactly through a dotenv parser. (Task 2 test `test_write_env_file_roundtrip_and_permissions`.)
5. **Log lines containing an email or phone number**, including inside nested dicts/exception messages → redacted to `[EMAIL]` / `[PHONE]` before output. (Task 3 tests.)
